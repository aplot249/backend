# 表单统计后端（Django + SimpleUI）

一个用于「工作内容统计」的后端项目，包含：

- 表单页面：`name`（必填）、`project`（必填）、`card_image`（工卡图片，必填）、`remark`（工作内容，选填）
- `name` / `project` 支持联想搜索（从后台导入的 Excel 数据中匹配）
- **姓名必须从列表里选**（不能自己敲）：没选就提交 → 提示
  `Please select your name from the list.` 并标红姓名框；
  绕过页面直接调接口也会被后端拦下（`We could not find your name in our records. Please select your name from the list.`）；
  选中/匹配到则把工卡**用外键挂到姓名库那个人身上**（详见下方「姓名：工卡 / 工时直接关联姓名库」）
- 工卡图片支持 jpg / png / webp / bmp / gif，单张不超过 10MB，提交前可预览
- 后台（SimpleUI）支持 Excel 导入姓名库、项目库，并导出提交记录（含工卡图片链接）

## 快速开始

### 1. 安装依赖

```bash
cd backend
pip install -r requirements.txt
```

### 2. 初始化数据库

```bash
python manage.py migrate
```

### 3. 创建后台管理员账号

```bash
python manage.py createsuperuser
```

### 4. 启动服务

```bash
python manage.py runserver
```

- 数据整理页：http://127.0.0.1:8000/summary/（需先登录后台）
- 后台管理：http://127.0.0.1:8000/admin/

## 姓名：工卡 / 工时直接关联姓名库（外键）

**工卡（`Submission`）和工时（`WorkHour`）都用外键 `person` 指向姓名库（`Name`）**，
两张表里不再各存一份姓名文本（迁移 `0008_person_fk`）：

| | 说明 |
|---|---|
| 改名 | 后台改姓名库的姓名，工卡 / 工时 / 整理页 / 统计 / PDF / 查询页**全部自动跟着变**，不需要任何同步代码 |
| 提交 | 姓名必须匹配到姓名库的人，工卡直接挂到那个人身上，**不可能再产生「姓名对不上库」的数据** |
| 删人 | `on_delete=PROTECT`：这个人还有工卡 / 工时就删不掉（后台会提示关联了多少条），避免误删 |
| 展示 | `submission.name` / `workhour.name` 是只读属性，**实时从姓名库取**，改名后立即生效 |

### 提交时怎么匹配到姓名库（`views._match_person()`）

| 情况 | 处理 |
|---|---|
| 归一化后完全相同（忽略大小写 / 空格 / `. : , ; _ - /`） | ✅ 通过，关联到那个人 |
| 单词完全一样、只是顺序不同（`md rasel mia` = `MIA MD RASEL`），且库里只有这一种写法 | ✅ 通过，关联到那个人 |
| 多写/少写词（`AL MD SHILON`）、拼写不同（`MD SOHEL RANA` ≠ `MD SHOHEL RANA`） | ❌ 拒绝，提示「请从列表里选你的姓名」 |

- 匹配不到时返回 `400` + `{"ok": false, "field": "name", "message": "We could not find your name in our records. Please select your name from the list."}`
- 页面表现：红色错误条 + 姓名输入框标红并聚焦 + 下方英文说明；重新输入即取消标红
- **前端强制「点选」**：只记录「点了建议列表里哪一项」（`selectedName`），
  自己敲的字不算；改动输入框内容即作废，必须重新点；失焦时若完整写下某个库内姓名则自动认作选中
- **搜索建议同步放宽**（`/api/search-name/`）：忽略大小写/标点/词序，并对个别字母打错
  做模糊兜底，返回的一律是库里的姓名 —— 工人点一下就是本人，不会卡住提交
  （排序：完全相同 → 前缀/包含 → 单词都在 → 部分单词 → 拼写相近）

### 迁移 0008_person_fk（已在线上库执行过）

1. 给两张表加可空 `person` 外键 → 2. 按当时存的姓名文本回填（**101 条工卡 + 153 条工时全部回填成功，0 落空**）
→ 3. 收成**非空** → 4. 唯一约束换成「人 + 项目 + 日期」 → 5. 删掉 `name` 文本字段

- 回填不上会**中止迁移**并打印 id（不会静默丢数据）
- 反向迁移会把 `name` 填回空字符串（姓名文本会丢），**执行前务必备份**

### 按人列出 / 删除工卡（`purge_unmatched_names`）

工卡都已关联姓名库，不存在「对不上库」的卡了。这个命令用来**按人核对 / 清理工卡**：

```bash
python manage.py purge_unmatched_names                   # 只列出，不删（默认）
python manage.py purge_unmatched_names --name SHILON      # 只看姓名含该关键字的
python manage.py purge_unmatched_names --skip-vacation    # 不列出「在休假」的记录
python manage.py purge_unmatched_names --delete           # 列出后要手输 DELETE 才删
python manage.py purge_unmatched_names --delete --yes     # 跳过确认（慎用）
```

- **先看后删**：默认纯预览；`--delete` 时列出每条记录的 `id / 项目 / 提交时间 / 图片大小 / 工时条数`，
  并要求手输 `DELETE` 才执行，输错或回车即取消
- 删除会连同**工卡图片文件**和挂在这些工卡上的**工时记录**一起删掉（外键级联），不可恢复；
  同一个 `transaction` 内完成，中途出错整体回滚
- 删除后打印剩余数量，方便核对

## Excel 导入（姓名库 / 项目库）

1. 登录后台 `/admin/`
2. 进入「姓名库」或「项目库」
3. 点击右上角「导入」(IMPORT) 按钮，选择 Excel 文件（.xlsx）

> Excel 文件要求：第一行为表头，表头必须包含 `name` 列（或 `姓名` 列），
> 内容即为要导入的姓名 / 项目名称。导入时会以 `name` 字段去重。

姓名库还包含以下字段（可在 Excel 里一并提供，也可在后台「姓名库」列表直接编辑）：

| 字段 | 说明 |
|---|---|
| `employee_no` | 工号 |
| `passport_no` | 护照号 |
| `hourly_rate` | 工时系数，即每小时金额（元/小时），用于与工作小时数相乘计算总金额 |

示例 Excel（姓名库）：

| name | employee_no | passport_no | hourly_rate |
|------|-------------|-------------|-------------|
| 张三 | E001        | P1234567    | 25.5        |
| 李四 | E002        |             | 30          |

> 只导入 `name` 列也可以，已有记录的工号 / 护照号 / 工时系数不会被清空。

## 考勤工卡 PDF 导出（`/summary/cards-pdf/`）

整理页顶部「导出考勤工卡 PDF」按钮，把每个工人的工卡抽成 PDF，供打印 / 存档 / 发人核对。

- **完全按姓名库取数**（和整理页同一套口径）：逐个姓名库的人列出，
  每人每个「项目 + 考勤周期」取**最新提交**的那张工卡（一个人干多个项目就都列出来，每张都出图）；
  项目名忽略大小写 / 空格 / 标点差异。每张写明 `最新工卡 2026-10-22 12:15:54 · 工时 … · 出勤 …`
- **完全按姓名库逐个列出**（工卡用外键关联姓名库，不存在「对不上库」的卡了）
- **休假 / 未提交工卡的工人直接跳过**，不进 PDF；某周期一张卡都没有时输出说明页（不报错）
- **周期筛选**：`?month=YYYY-MM`，周期按工卡**提交时间所在月份**判定
  （详见下面「考勤周期与各月互不影响」）；`?month=all` 导出所有周期各自的最新卡
- **项目名归一化**：`_normalize_name` 把 `. : , ; _ - /` 也当空格，
  同一个项目被写成两种样子时算作一个（姓名已走外键，不需要再归一化比对）
- 版面：**左右两栏 × 上下两行，一页 4 个人**；图片按格子高度自动等比缩放
  （一格最多占半页，一个人多张卡时自动把每张压小），且保证一个人的内容不会被跨页拆开
- 口径与整理页一致：只取每个「人 + 项目」**最新提交**的那张工卡
- **休假 / 未提交工卡的工人也会列出来**：姓名行标注「在休假」，正文写明
  「在休假，本周期无考勤工卡」或「本周期无考勤工卡（未提交工卡）」，不会漏人
- 首页概览：考勤周期、生成时间、总人数 / 有工卡人数 / 工卡张数；每页页脚有页码
- 筛选：`?month=all`（默认，全部工卡）或 `?month=YYYY-MM`（只导该考勤周期的工卡，
  周期按「提交时间所在月份」判定）
- 图片处理：PIL 先把大图降采样到宽 ≤1100px、转 JPEG（quality 62）再写入，
  避免原图（几 MB 一张）把 PDF 撑爆；图片读取失败会写「（工卡图片无法读取）」而不是中断
- 依赖 `reportlab`（已加进 requirements.txt，部署需 `pip install reportlab`），
  中文用 reportlab 自带 CID 字体 `STSong-Light`，无需外挂字体文件

> 99 人 / 103 张工卡图（休假 / 未提交的 51 人已跳过）时约 29 页、15 MB、生成 11 秒左右；
> 工卡再多会更久，页面按钮点了会显示「生成中...」。若服务器（gunicorn/uwsgi）超时时间 < 60 秒，建议调大。

## 首页开关：填报表单 / 工时查询（数据库变量控制）

后台 **系统开关**（`formapp.SystemSetting`，全局只有一条记录，pk=1）用数据库变量控制首页展示哪个页面：

| `form_enabled` | 首页 `/` | `/check/` | `POST /api/submit/` |
|---|---|---|---|
| `True`（默认） | 完整的工卡填报表单 | 正常访问 | 正常提交 |
| `False` | 仍是 `/`，但表单换成「当前填报阶段已结束，进入查询系统」的提示页 + 去查询页的按钮 | 正常访问 | **403 拒绝**（防止绕过页面直接调接口） |

- **两个页面的路由始终独立**：`/` 是填报页、`/check/` 是查询页，关闭填报不会把 `/` 变成查询页，
  只是在 `/` 上给出友好提示（中文 + 英文双行），并提供「进入查询系统 →」按钮跳到 `/check/`
- **后台管理员不受开关限制**：开关关闭时，只要浏览器里登录着后台账号
  （`is_staff` 或超级用户），`/` 照样显示完整填报表单，页面顶部多一条橙色提示
  「管理员预览：工人端当前已关闭填报」；`POST /api/submit/` 也同样放行，
  方便自己补录 / 测试。工人（未登录）和只登录了前台的普通账号仍然被拦
  （判断见 `views._is_backend_admin()`）
- 后台位置：管理后台 → `FORMAPP` → **系统开关** → 勾/取消「展示填报表单」→ 保存，立即生效，不用重启
- 关闭填报时：填报页隐藏表单与顶部「Check my work hours →」小链接（只留居中提示），
  查询页显示 `Work card submission is closed. You can only check your work hours here.`
  并隐藏「← Back to the submission form」返回链接（避免点了又回到自己）
- 数据表随迁移 `formapp/migrations/0007_systemsetting.py` 建立，部署需执行 `python manage.py migrate`
- 代码入口：`SystemSetting.get_setting()`；首页渲染在 `form_view()` 里按开关二选一

## 工时查询页（`/check/`，templates/check.html）

给**工人自己**查询用的只读页面：输入姓名 → 列出他每个项目**最新提交工卡**上已录入的工时。

- **两个输入框：姓名 +（工号 或 护照号），两项都对上同一个人才返回数据**
  - 姓名联想：`GET /api/check-search/?q=关键字`（只按姓名联想）
  - 查询：`GET /api/check-hours/?name=姓名&code=工号或护照号`
- 匹配规则：姓名用 `_normalize_name`（去首尾与连续空格 + 统一大写），
  工号 / 护照号用 `_normalize_code`（去掉所有空白 + 统一大写），**大小写、空格都不敏感**
- 校验顺序与提示（返回 `field` 指明哪一项填错，页面上对应输入框标红）：
  1. 姓名查不到人 → `field=name`：姓名拼写不对
  2. 姓名对、但工号 / 护照号不属于这个人 → `field=code`：**工号或护照号输入有误**
  3. 该姓名在库里没有工号也没有护照号 → `field=code`：请联系现场办公室补录
  4. 同名多人 → 返回候选列表让工人自己选一个
- 护照号在页面上脱敏展示（只留前 2 位与后 2 位）；工号完整显示
- **每个项目的工时下方显示那次提交的工卡图片**（`card_image_url`，接口随项目一起返回）：
  工人可以对照卡核对自己的工时；点图片看原图；`loading="lazy"` 懒加载；
  没图（例如「在休假」的系统生成卡）或文件已删除时不显示空的图片框
  （后者显示 `Work card image is not available.`）
- 口径与整理页一致：只取该周期「人 + 项目 + 周期」最新工卡的工时，**其它周期 / 历史提交不展示**；
  工时按天列出并按月份分组，同时给出项目合计与个人总工时
- **周期选择**：页面上有考勤周期下拉（默认当前月份所属周期），换周期看历史；
  某个周期工人还没交卡时提示 `No work card has been submitted under this name in <周期>`
- **只读**：页面没有任何编辑 / 删除入口，也没有暴露写接口
- 展示字段：姓名、工号、项目数、总工时、每个项目的最近提交时间 + 出勤天数 + 每日工时；
  0 工时的日期不列出；「在休假」项目显示 `On leave`
- 支持 `/check/?q=姓名` 直接带出结果（可做成固定链接发给工人）
- 布局与表单页一致：一屏展示、页面不出现滚动条（结果区内部滚动），手机单列 / 电脑 ≥860px 多列

## 考勤周期：每个月各做各的，互不影响

**周期 = 上月 21 日 ~ 本月 20 日**，每个月只做一次统计：

| 做什么 | 提交时间 | 所属周期 | 周期区间 |
|---|---|---|---|
| 10 月统计 | 2026 年 **10 月**提交 | `2026-10` | 2026-09-21 ~ 2026-10-20 |
| 11 月统计 | 2026 年 **11 月**提交 | `2026-11` | 2026-10-21 ~ 2026-11-20 |
| 12 月统计 | 2026 年 **12 月**提交 | `2026-12` | 2026-11-21 ~ 2026-12-20 |

**判定规则：工卡属于哪个周期，按「提交时间所在月份」算**（`_payroll_month(created_at)`）。
> 为什么不用「21 号分界」：实际都是 21 号之后才交上个月的卡（现有 101 张卡全部在 10/22~23 提交），
> 若按 21 号分界，9/21~10/20 这批卡的提交时间会被算进 2026-11，全错。

**「最新工卡」现在是三维的：人 + 项目 + 周期**（以前只有「人 + 项目」）。因此：

| 场景 | 以前（有问题） | 现在 |
|---|---|---|
| 11 月交了新卡 | 10 月那张被降级成「历史卡·只读」，从合计 / 导出里消失 | 各周期各留各的最新卡，**两个周期的卡都能正常录入 / 导出** |
| 12 月回头补导 10 月 Excel | 缺人缺工时 | 选 `2026-10` 导出，数据完整 |
| 整理页已提交 / 未提交 | 交过卡就算「已提交」，与周期无关 | 按**所选周期**判定：11 月没交卡的人显示「未提交」 |
| check 工人查询页 | 看到的是最新那张卡（可能是上个月的） | 按周期查，只看所选周期的最新卡 |

各处的周期从哪来：

- **整理页 `/summary/`**：顶部「统计周期」下拉（`?period=YYYY-MM`），页面的人数 / 已提交 / 未提交 /
  累计工时、以及 Excel / PDF 导出**全部只算这个周期**；默认选中「最近提交过工卡的周期」
- **check 查询页 `/check/`**：页面上的 `Attendance period` 下拉，默认当前月份所属周期
- **导出**：`/summary/export/?month=YYYY-MM`、`/summary/cards-pdf/?month=YYYY-MM`（`month=all` = 所有周期各自的最新卡）
- **保存 / 合计接口**：以该工卡**自己的周期**为准（`_card_period_key`），所以上个月的历史卡在自己周期里仍能补录

> admin「姓名库」里的**「工卡 / 工时」两列是全历史累计**（`obj.submissions.count()` /
> `obj.work_hours.count()`），**不会按月清零**，且「工时」列是**记录条数**不是小时数——要按月统计请用整理页或导出。

## 数据整理页（/summary/）

### 从 admin 后台直接进入

后台用的是 **SimpleUI** 主题，左侧菜单里已经挂了一个入口（点开是后台内的一个标签页，用 iframe 加载整理页）：

```python
# config/settings.py
SIMPLEUI_CONFIG = {
    "system_keep": True,          # 保留系统自动生成的菜单（姓名库 / 项目库 / 提交记录…）
    "menus": [

```

- 不带 `models` 的菜单项就是**直达链接**（SimpleUI 会用 iframe 打开它的 url）
- 想「登录后台就直达整理页」：再加一行 `SIMPLEUI_HOME_PAGE = "/summary/"`（首页标签页会被换成整理页）
- 另外还有个**整页版** `/admin/summary/`：把整理页嵌在 admin 页面框架里（`templates/admin/summary_embed.html`），

- 能让 iframe 正常工作的关键：`summary_view` 上加了 `@xframe_options_sameorigin`
  （项目开了 `XFrameOptionsMiddleware`，默认是 `DENY`，不加会被浏览器拦掉）

### AI 识别工时（框选 → 逗号文本 → 依次填表）

**为什么要框选**：整张卡一起识别时，AI 要同时猜日期和工时，容易错；改成你框住工时那一列，
AI **只按顺序读数字**，准确率要高得多。

四步走：

1. **框选**：图片上方有一对切换按钮 **「裁剪」/「AI 识别区」** ——
   点「AI 识别区」后鼠标变十字，**在图上按住左键拖**就画出紫色识别区
   （框住「当天工作小时数」那一列，配合旋转 / 缩放；画完还能拖着挪、拉角微调）。
   紫色框和蓝色裁剪框**完全独立**，互不影响；**不画**就是整张卡
2. **识别**：点「AI 识别选区」→ 只把这块选区发给 AI，读出 `10,10,13,0,8` 这样的逗号分隔文本
3. **编辑**：结果出现在下面的输入框里，**可以直接改** —— 加、删、改顺序都随你；
   想让某天从后面开始填，就在前面补几个 `0,`（例如 `0,0,10,10`）
4. **填入**：点「填入工时表」→ 按逗号拆分，从**光标那格**开始一格一格往日历里填
   （黄底格子 = 本次填的），核对后点「保存工天数据」入库

**光标（连续识别用）**：一张卡分几次框选识别时，不用每次都从头填 ——

- 填完光标自动停在**下一格**（紫色边框 + 小三角 ▼ 标住），下次识别直接接着填
- **点任意格子**（别点在输入框里）即可把光标挪过去；「回到第一天」按钮移回周期开头
- 光标已到周期末尾再点填入会被拦下（提示挪光标）；换卡 / 换周期光标归零

**边界与容错**：

- 识别结果**不写数据库**，全程只是填表建议，最后仍走原有保存接口
- **从周期第一个格子开始依次填**（不是按日期匹配）：`第 N 个数 = 周期第 N 天`
- 数字比周期天数多 → 多出来的丢弃并提示；读不出来的项（如 `abc`）按 **0 占位**并在提示里点名，
  **不会让后面串位**
- `10+3` 自动算 13，`10½` / `10.5` 都行，`10h` 去掉单位；中英文逗号、顿号、分号、空格都能分隔；
  单个值夹在 0~24
- 识别用的是**紫色 AI 识别区**框住的那一块（含弹窗里的旋转效果），不是原图整张；
  蓝色裁剪框只归「保存并替换原图」用 —— **两套选区互不影响**：
  框了识别区再点保存，存出来的还是裁剪框那块图，反之亦然
- 没框 AI 识别区就点识别 = 整张卡（会提示「框选会更准」）；换卡自动重置两个选区
- 每次识别只发一张小图（选区压到 1400px 以内），按 AI 服务商计费

**配置**（任何 OpenAI 兼容的视觉模型接口都行；当前用**智谱 GLM-4.6V**）：

```bash
# 当前 settings.py 里的默认值就是智谱（也可用环境变量覆盖）：
#   AI_VISION_BASE_URL = https://open.bigmodel.cn/api/paas/v4
#   AI_VISION_API_KEY  = （写在 settings.py 里，建议改成环境变量，避免随代码进 git）
#   AI_VISION_MODEL    = glm-4.6v
# 换其他服务商示例：
set AI_VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1   # 阿里云百炼 qwen-vl-max
set AI_VISION_API_KEY=sk-xxxx
set AI_VISION_MODEL=qwen-vl-max
```

> **推理模型提速**：GLM-4.5V / 4.6V 默认会先「思考」一大段再回答，读一张卡要 90 秒以上。
> 已默认发送 `thinking: disabled` 关掉思考（实测 90s 超时 → **2~20s 出结果**）；
> 想恢复推理就设 `AI_VISION_DISABLE_THINKING=0`。超时默认 180 秒（`AI_VISION_TIMEOUT`）。

配置好先在服务器上用命令验证（不写库；这是**整卡模式**，页面用的是选区模式）：

```bash

python manage.py ai_recognize_test 30 --month 2026-10
```

## 空格处理

姓名和项目名统一「去首尾空格 + 中间连续空格合并成一个」：

1. **写入时自动清理**：`Name` / `Project` 的 `save()` 会走 `clean_spaces()`，
   工卡 / 工时的 `project` 同样清理；**姓名不存文本**（走外键），不会有空格不一致的问题
2. **存量数据清洗**（现在只清洗项目名，姓名以姓名库为准）：

   ```bash
   python manage.py trim_names           # 只预览
   python manage.py trim_names --apply   # 实际清洗（姓名库 / 项目名）
   ```

   姓名库修整后若与已有姓名重名，会保留工号、护照、单价更全的一条，
   并把被合并那个人的工卡 / 工时一起转过去；
   项目名修整后若撞上「人 + 项目 + 日期」唯一约束，只保留一条

## 工时对不上的排查命令

整理页合计（`总工时`）、打卡弹窗、Excel 导出三处口径：

- 弹窗：按「工卡 id」直读该卡的工时
- 整理页合计 / 导出：按「姓名库姓名」匹配 + **只统计该周期「人 + 项目 + 周期」最新工卡**上的工时

所以「弹窗有数字、整理页却是 0」通常是下面两个原因之一：

1. **姓名不一致**：姓名库里存的是 `' ABDUL MOJID'`（带空格）或大小写不同，
   而工卡里是 `ABDUL MOJID`，Python 字典按精确字符串匹配就取不到 → 合计 0
   （代码已按「去首尾空格 + 连续空格合并 + 统一大写」归一化匹配，见 `_normalize_name`）
2. **工时挂在历史工卡上**：录完之后，同一个人在同一个项目下又提交了一张新工卡，
   旧卡变成历史卡，合计与导出会把它过滤掉

排查与修复：

```bash
python manage.py diagnose_hours                        # 列出所有有工时的人
python manage.py diagnose_hours --name "ABDUL MOJID"   # 只看某个人（看姓名匹配 / 是否最新卡 / 两个口径的合计）
python manage.py consolidate_work_hours                # 预览：多少行需要改挂到最新卡、多少重复行
python manage.py consolidate_work_hours --apply        # 实际把历史卡上的工时改挂到最新卡并去重
```

## 导出 Excel（/summary/export/）

| 样表列 | 内容 |

## 生产环境部署（`DEBUG=False`）

静态文件与上传文件在 `DEBUG=False` 时不会由 `runserver` 自动提供，需要额外处理：

### 1. 收集静态文件

```bash
python manage.py collectstatic     # 输出到 staticfiles/
```

### 2. 用 Nginx 托管 static / media（推荐）

```nginx
location /static/ {
    alias /srv/form-backend/staticfiles/;
    expires 30d;
    access_log off;
}

location /media/ {
    alias /srv/form-backend/media/;
    expires 30d;
    access_log off;
}
```

> `alias` 路径结尾的 `/` 要与 `location` 一致；同时确保运行 Django 的账号对 `media/` 有写权限（上传用），Nginx 账号有读权限。

### 3. 未使用 Nginx 时的兜底方案

项目已内置：当 `DEBUG=False` 时，`/media/` 由 Django 的 `protected-media` 路由提供，
**仅允许已登录的后台用户访问**（工卡属于敏感信息）。此时无需额外配置即可在后台看到图片，
但性能不如 Nginx，正式环境仍建议按第 2 步配置。

### 4. 时区问题

若后台按时间筛选/分组时报错 `Database returned an invalid datetime value`，
说明 MySQL 未加载时区表，在服务器上执行：

```bash
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql
```
